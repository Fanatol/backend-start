## Теоретическое обоснование

**CRUD** — акроним, обозначающий четыре базовые операции над данными: Create (создание), Read (чтение), Update (обновление), Delete (удаление). В REST-подобных API эти операции реализуются через HTTP-методы: POST — создание, GET — чтение, PUT/PATCH — обновление, DELETE — удаление.

**HTTP-методы** имеют разную семантику. GET — безопасный и идемпотентный (не меняет данные, повторный вызов даёт тот же результат). POST — не идемпотентный (два одинаковых запроса создадут два ресурса). PUT — идемпотентный (полная замена ресурса). PATCH — частичное обновление. DELETE — идемпотентный (повторное удаление не меняет состояние).

**Коды состояния HTTP** сообщают клиенту о результате запроса: 200 — успех, 201 — ресурс создан, 204 — успех без тела ответа (например, при DELETE), 400 — невалидные данные, 404 — ресурс не найден, 500 — внутренняя ошибка сервера.

**Хранение данных в памяти** (массив объектов) используется в учебных целях: не требует установки БД, обеспечивает быстрый доступ. Недостаток — данные теряются при перезапуске сервера.

## Контрольные вопросы

**1. Что такое CRUD? Расшифруйте каждую букву.**
CRUD — акроним для четырёх базовых операций над данными: Create (создание), Read (чтение), Update (обновление), Delete (удаление).

**2. Какие HTTP-методы соответствуют операциям CRUD?**
Create → POST, Read → GET, Update → PUT/PATCH, Delete → DELETE.

**3. Что такое идемпотентность HTTP-методов? Какие методы идемпотентны?**
Идемпотентность — свойство метода давать одинаковый результат при повторном вызове. Идемпотентны GET, PUT, DELETE. POST — не идемпотентен.

**4. Какой код ответа возвращается при успешном создании ресурса (POST)?**
201 Created.

**5. Какой код ответа возвращается при успешном удалении ресурса?**
200 OK (с телом) или 204 No Content (без тела). В работе используется 204.

**6. Что такое middleware в Express? Для чего используется express.json()?**
Middleware — функция, выполняющаяся между получением запроса и отправкой ответа. `express.json()` парсит JSON-тело запроса и помещает результат в `req.body`, без него `req.body` пустой.

**7. Как получить параметры из тела POST-запроса в Express?**
Через `req.body` (при условии, что подключён middleware `express.json()`).

**8. Как получить параметр из URL (например, ID)?**
Через `req.params.id` для маршрута вида `/users/:id`.

**9. Как найти элемент в массиве по ID?**
`users.find(el => el.id === id)` — вернёт объект; `users.findIndex(el => el.id === id)` — вернёт индекс (или -1).

**10. Какой код ответа возвращается, если ресурс не найден?**
404 Not Found.

**11. В чём разница между PUT и PATCH?**
PUT полностью заменяет ресурс (все поля перезаписываются), PATCH обновляет только переданные поля, остальные сохраняются.

**12. Как реализовать поиск по коллекции (query-параметр search)?**
Извлечь `req.query.search`, отфильтровать массив через `.filter()` с `.toLowerCase().includes()` для регистронезависимого поиска.

**13. Как реализовать сортировку по полю?**
Извлечь `req.query.sort` и `req.query.order`, провалидировать допустимые значения, применить `.sort()` к копии массива. Для чисел — вычитание (`a.age - b.age`), для строк — `localeCompare`.

**14. Как реализовать пагинацию (постраничный вывод)?**
Извлечь `req.query.page` и `req.query.limit`, вычислить `skip = (page - 1) * limit`, применить `slice(skip, skip + limit)`.

**15. Как валидировать входные данные (например, что price — число)?**
Проверять через `Number.isInteger()` или `typeof`, а также диапазон допустимых значений. При ошибке возвращать 400 Bad Request.

**16. Какие коды ответов используются при ошибках валидации?**
400 Bad Request.

**17. Как вернуть 204 No Content при DELETE?**
`res.status(204).end()` — без тела ответа.

**18. В чём разница между res.json() и res.send()?**
`res.json()` явно устанавливает `Content-Type: application/json` и сериализует объект. `res.send()` более универсален — сам определяет тип (строка → text/html, объект → JSON).

**19. Как избежать дублирования ID при создании новых элементов?**
Использовать счётчик `nextId`, который увеличивается после каждого создания. ID назначает сервер, а не клиент.

**20. Что такое express.json() и почему без него req.body пустой?**
Middleware, который читает тело запроса, парсит JSON и помещает результат в `req.body`. Без него Express не знает, что тело — JSON, и оставляет `req.body` пустым.

**21. Как реализовать частичное обновление (PATCH)?**
Найти объект по id, провалидировать только переданные поля, обновлять поля через `if (req.body.field !== undefined) user.field = req.body.field`. Не заменять объект целиком.

**22. Как реализовать массовое удаление элементов?**
`users.length = 0` (или `splice`) — обнуление массива in-place. Вернуть 200 OK с количеством удалённых.

**23. Как реализовать массовое создание элементов?**
Принять массив в `req.body`, проверить `Array.isArray`, провалидировать каждый элемент, при успехе создать всех с уникальными id, вернуть 201 Created с массивом созданных.

**24. Как реализовать глобальный обработчик ошибок?**
Middleware с **четырьмя** аргументами `(err, req, res, next)`, размещённый **после** всех маршрутов. Express распознаёт его по 4 аргументам и вызывает при исключениях.

**25. Как логировать запросы в файл?**
Через модуль `fs` — `fs.appendFile("access.log", строка + "\n", callback)` внутри middleware логирования.

**26. Что такое REST API и какие принципы лежат в его основе?**
REST — архитектурный стиль для построения API: клиент-сервер, отсутствие состояния на сервере между запросами, единый интерфейс (ресурсы + HTTP-методы), кэшируемость, многоуровневая архитектура.

**27. Как организовать структуру проекта для масштабируемого CRUD API?**
Разделение на слои: маршруты (routes), контроллеры (controllers), сервисы/модели (services/models), middleware, утилиты, конфигурация. Каждая сущность — в своём файле.

**28. Какие существуют стратегии генерации уникальных ID?**
Счётчик `nextId++`, `Math.max(...ids) + 1`, UUID (`crypto.randomUUID()`), автоинкремент в БД.

**29. Как защитить API от слишком больших запросов?**
Ограничение размера тела (`express.json({ limit: "10kb" })`), лимит на `limit` в пагинации (не более 100), rate limiting.

**30. Как реализовать связь между сущностями (например, задачи и пользователи)?**
Хранить поле-ссылку (например, `userId` в задаче). При запросе связанных — фильтровать по этому полю. Для связи «многие-ко-многим» — массив id или отдельная таблица связей.
